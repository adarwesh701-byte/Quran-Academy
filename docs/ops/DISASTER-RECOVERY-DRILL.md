# خطة النسخ الاحتياطي واختبار الاستعادة

## ما يجب نسخه
1. الكود والمستودع وسجل الإصدارات.
2. مخطط PostgreSQL وmigrations وRLS وGRANTs وFunctions وTriggers.
3. بيانات قاعدة البيانات وفق سياسة خصوصية واحتفاظ معتمدة.
4. ملفات Supabase Storage مع أسماء Buckets وخصوصيتها وMetadata.
5. تعريفات Edge Functions وإصداراتها وإعدادات البيئة، دون وضع الأسرار داخل الأرشيف.
6. إعدادات DNS/Vercel/المزودين وإجراءات تدوير الأسرار، لا قيم الأسرار نفسها في المستودع.
7. محتوى الكتب والتلاوات والملفات الأصلية مع بصمات تحقق.

## قواعد التخزين
- نسخة مشفرة خارج حساب الاستضافة الأساسي، مع نسخة منفصلة Offline عند الإمكان.
- فصل النسخ اليومية/الأسبوعية والاحتفاظ حسب سياسة مكتوبة.
- تقييد الوصول وتسجيل التنزيل والاستعادة.
- لا ترسل ملفات Backup التي قد تتضمن أسرارًا أو بيانات طلاب إلى Claude أو محادثات عامة أو مستودعات عامة.

## اختبار الاستعادة الدوري
1. أنشئ مشروع Supabase تجريبيًا معزولًا.
2. استعد Schema أولًا ثم تحقق من Extensions وRoles وPolicies وFunctions.
3. استعد البيانات الاصطناعية/المصرح بها والملفات مع التحقق من عدد السجلات والبصمات.
4. انشر Edge Functions من المصدر الموثوق وأدخل الأسرار من لوحة Secrets.
5. اختبر تسجيل الدخول والأدوار وقراءة/كتابة بيانات الاختبار والملفات.
6. اختبر مسارات الدفع Sandbox فقط.
7. اختبر تشغيل التلاوات المسجلة وتزامن المحتوى، ولا تستبدل القرآن أو التلاوات بـ TTS.
8. سجّل RPO الفعلي (كم بيانات يمكن فقدها) وRTO الفعلي (زمن العودة).
9. لا تعلن نجاح النسخ الاحتياطي قبل نجاح استعادة تجريبية كاملة.

## استعادة صلاحية المالك
لا تستخدم تعليمات عامة لترقية `profiles.role` دون معرفة مخطط الصلاحيات وآلية المزامنة مع Auth. نفّذ إجراء break-glass فقط من مالك مشروع Supabase الموثق، وبعد نسخة احتياطية ومراجعة شخص ثانٍ، وسجّل المنفذ والسبب والوقت والهوية. لا تضع SQL ترقية مالك قابلًا للنسخ في دليل عام.
