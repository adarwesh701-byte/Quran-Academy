# مراقبة التشغيل والاستجابة للحوادث

هذه وثيقة تشغيل وليست تكامل مراقبة منفذًا. لم تتم إضافة مزود Telemetry أو إرسال بيانات مستخدمين إلى طرف ثالث؛ اختيار المزود وربط مفاتيحه يحتاج قرار المالك.

## مؤشرات يجب جمعها
- أخطاء JavaScript غير المعالجة وUnhandled Promise Rejections.
- فشل تسجيل الدخول وتجديد الجلسات.
- أخطاء Supabase REST/RPC/Edge Functions حسب اسم الوظيفة ورمز الحالة، دون تسجيل Authorization أو مفاتيح أو بيانات شخصية.
- فشل تشغيل/تحميل الصوت، مع عدم تسجيل محتوى التلاوة أو صوت المستخدم.
- فشل إنشاء/تأكيد الدفع ومدة Webhook وتكراره، مع معرف طلب داخلي غير حساس.
- Core Web Vitals: LCP وINP وCLS، مع عينة مجهولة الهوية وبموافقة/إعدادات خصوصية مناسبة.
- صحة النسخ الاحتياطي ونتيجة آخر اختبار استعادة.

## تنبيهات مقترحة
- ارتفاع 5xx أو أخطاء Edge Function فوق خط الأساس.
- فشل Webhook أو تراكم الطلبات المعلقة.
- انخفاض نجاح تسجيل الدخول فجأة.
- ارتفاع LCP/INP أو أخطاء تحميل الملفات.
- فشل النسخة الاحتياطية أو عدم نجاح اختبار الاستعادة الدوري.

## قواعد الخصوصية
- ممنوع تسجيل كلمات المرور، access/refresh tokens، Service Role Key، HMAC secrets، بيانات البطاقة، أو محتوى خاص بالطالب.
- قلّل الاحتفاظ بالسجلات، وقيّد الوصول إليها، وسجّل الوصول الإداري.
- افصل بيانات Staging عن Production.

## Runbook أولي للحادث
1. صنّف الحادث: أمان، دفع، توفر، بيانات، صوت/محتوى.
2. أوقف الميزة المتأثرة فقط إن أمكن، ولا توقف تسجيل الدخول أو المنصة بالكامل دون داعٍ.
3. احتفظ بالأدلة والسجلات المنقحة ولا تحذفها.
4. إن كان السبب إصدار واجهة، ارجع إلى آخر Deployment سليم.
5. إن كان السبب بيانات، لا تنفذ restore فوق Production قبل تحديد نقطة الاستعادة وفقد البيانات المقبول وموافقة المالك.
6. غيّر الأسرار المتأثرة من لوحة المزود، لا داخل ملفات Frontend.
7. اختبر المسارات الأساسية ثم وثّق السبب الجذري والإجراء الوقائي.
