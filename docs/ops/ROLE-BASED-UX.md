# تجربة حسب الدور — قواعد التصميم والتنفيذ

الواجهة تعرض أدوات مناسبة للدور، لكنها ليست حدًا أمنيًا. كل عملية يجب أن تُصرّح بها قاعدة البيانات أو Edge Function على الخادم.

## مبادئ تجربة المستخدم
- الطالب: الصفحة الرئيسية تعرض الدروس المسندة، التقدم، الواجبات، الاختبارات، ومواعيد المعلم. لا تعرض أدوات إدارة غير لازمة.
- المعلم: تعرض الفصول المسندة، قوائم الطلاب المصرح بها، التقييمات، الحضور، والتقارير التعليمية.
- المدير: يعرض نطاق الإدارة المفوض فقط، مع فصل إعدادات النظام والأسرار عن مهام الدعم اليومية.
- المالك: مركز تحكم شامل مع تأكيد إضافي للعمليات الحساسة، معاينة قبل النشر، سجل تغييرات، ورسائل نجاح/فشل صادقة.
- الزائر: محتوى تعريفي ومناهج عامة ومسارات تسجيل واضحة.

## متطلبات قبل التنفيذ
- استخراج أسماء الأدوار الفعلية من قاعدة البيانات؛ لا نفترض أن `owner/admin/teacher/student` هي القيم الوحيدة.
- رسم مصفوفة Role × Resource × Action من RLS وRPC وEdge Functions.
- منع الاعتماد على role مخزن في Local Storage أو قيمة يرسلها العميل.
- اختبار الوصول المباشر لكل Route وAPI حتى لو أخفت الواجهة الزر.
- احترام اللغة واتجاه RTL/LTR وتفضيلات الوصول لكل دور.

لم تُعدّل واجهات الأدوار في هذه الدفعة لأن مخطط الصلاحيات الفعلي غير متوفر في الأرشيف.
